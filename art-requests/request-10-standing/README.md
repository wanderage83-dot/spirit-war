# 요청 10 · 20명 정지 4방향

최종 범위는 20명 각각 fr/fl/br/bl 정지 이미지다. 첨부 브리프의 걷기 시트 단계는 사용자 지시로 취소되었다. 방향마다 이미지 생성 도구를 사용했으며 좌우 반전 변환으로 만들지 않았다.

## 결과

- [규격본 목록](exports/index.html): 보병 68장 **256×256**, 기병 12장 **384×384**, 모두 투명 RGBA PNG.
- `exports/<name>/<name>-<dir>.png`: 최종 규격 출력 파일 80장.
- `<name>/<name>-<dir>.png`: 보존된 고해상도 생성 원본 80장, 각 1254×1254.
- [원본 목록](index.html), [원본 명세](manifest.json), [규격본 명세](exports/manifest.json).
- `exports/previews/`: 5명씩 네 방향을 비교하는 미리보기. 녹색 선은 표시상 기준선이며 개별 PNG에는 포함하지 않았다. 기병은 미리보기에서만 256px로 축소 표시한다.
- `source/`: 첨부된 수정 참고 ZIP과 원문 브리프. 원문의 과거 범위보다 사용자 최종 지시가 우선한다.

기병은 수정 참고 ZIP의 실제 그림에 따라 **호연·사율·비연**이다.

## 크기와 발 정렬

사용자 승인에 따라 별도 이미지 처리 도구로 고해상도 원본에서 규격본을 출력했다. 캐릭터마다 네 방향의 머리 위 기준점부터 발까지 표시 높이를 맞추고, 발 지지 영역 중심을 캔버스 수평 중심에 맞췄다. 무기·머리·망토가 잘리지 않도록 네 방향 모두 들어가는 공통 표시 높이를 선택했다. 보병 발 기준선은 y=239, 기병은 y=359다. 검 끝이 발보다 낮은 귀왕은 네 방향 모두 y=223으로 맞춰 검의 아래쪽 여백을 확보했다. 귀왕 fr은 검 끝 대신 장화 위치를 직접 지정했다. 발 경계는 보간에 따라 ±1px다.

희미한 가장자리 알파 노이즈가 정렬을 방해하지 않도록 측정에만 알파 16/255 기준을 사용했다. 출력은 원본 전체의 배율·위치 변환이며, 미리 곱한 알파로 보간해 투명 경계의 색 번짐을 줄였다. 좌우 반전·재채색·덧그림은 하지 않았다. 원본의 의상·체형 등 그림 자체의 차이를 기하학적 정렬만으로 수정하지는 않는다.

## 검증

- 20명 × 4방향 = 80개 규격 파일, 누락 없음.
- 보병 68개는 256×256, 기병 12개는 384×384.
- 모두 RGBA, 투명 픽셀과 불투명 픽셀 존재.
- 유효 알파 경계 여백과 발 기준선 ±1px 확인.
- 생성 원본 80개의 SHA-256 모두 변경 없음.
- 이 검사는 얼굴·의상·해부학적 손 일치를 자동 보증하지 않는다.

ZIP 배포본에는 규격본·미리보기·명세만 포함한다. 원본과 재출력 도구는 GitHub 작업 브랜치에 보관한다.

재출력: Pillow·NumPy가 설치된 환경에서 `python3 art-requests/request-10-standing/export_sizes.py`. 실행 위치와 무관하게 스크립트 위치에서 원본을 읽는다. 원본 해시가 명세와 다르면 중단한다.

`art/request-10-standing-20` 브랜치에 백업했으며 `main`에는 병합하지 않았다. 게임의 기존 에셋이나 실행 코드에는 연결하지 않았다.
